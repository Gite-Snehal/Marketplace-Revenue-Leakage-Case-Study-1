# Marketplace-Revenue-Leakage-Case-Study-1

### Marketplace Revenue Leakage, Customer Economics & Commercial Decision-Making

## 1. Project Overview

A SQL-based business analytics case study focused on marketplace revenue performance, customer economics, discount dependency, and commercial risk. The project uses transaction data to identify business patterns and support data-driven decisions.

## 2. Objectives

- Analyze GMV, delivered GMV, and contribution.
- Evaluate customer concentration and repeat purchases.
- Identify discount dependency across product categories and acquisition channels.
- Examine customer acquisition cohorts.
- Assess the potential impact of a 10% discount reduction.

## 3. Tools & Skills

**Tools:** MySQL, SQL

**Skills:**

- Common Table Expressions (CTEs)
- Window Functions: `LAG()`, `NTILE()`, `PERCENT_RANK()`, `RANK()`
- Aggregate Functions: `SUM()`, `COUNT()`, `AVG()`
- `CASE` statements and conditional aggregation
- Subqueries
- Date functions and data validation
- Business KPI analysis and scenario analysis

## 4. Project Structure

- **DATABASE/** — Marketplace transaction dataset (CSV)
- **MYSQL/** — SQL queries and database analysis
- **PDF/** — Project overview PDF
- **README.md** — Project overview, objectives, tools, skills, and key findings

## 5. Analysis Highlights

- **Total GMV:** 561,318.00
- **Delivered GMV:** 447,907.10
- **Contribution Proxy:** 390,592.92
- The top 10% of customers account for 34.10% of delivered GMV.
- Beauty has the highest category discount rate at 16.53%.
- Affiliate has the highest channel discount rate at 17.06%.
- Fashion was flagged as a high-risk category in the case study.

## 6. Key Learning Outcomes

- Applied SQL to a realistic marketplace business case.
- Practiced advanced SQL techniques for business analysis.
- Learned to evaluate customer concentration and discount strategies.
- Connected SQL outputs with commercial decisions.
- Recognized the importance of validating data before interpreting results.

## 7. Disclaimer

This project is for educational and portfolio purposes. The findings are based on the available case-study dataset and its SQL outputs. Date-parsing issues affect monthly and acquisition-cohort analysis, so those results require further validation before drawing conclusions.
